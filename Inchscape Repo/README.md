# Inchcape Suzuki collision-parts forecasting

This repository contains the forecasting workflow for monthly Suzuki collision-part demand in Chile. It is structured so that inputs, reproducible code, tables, and figures are kept separate.

## Repository layout

| Location | Purpose |
| --- | --- |
| `data/raw/` | Source sales extract; do not edit. |
| `data/external/` | Monthly external features supplied with the project. |
| `data/processed/` | Clean, model-ready collision-part data split by demand type. |
| `src/` | Reproducible modelling and evaluation scripts. |
| `notebooks/` | Optional notebook workspace (may be empty). |
| `results/tables/` | Analysis outputs in CSV format. |
| `results/figures/` | Labelled PNG charts generated by the scripts. |
| `docs/` | Source data dictionary and project documentation. |

## Quick start

Create an environment with the packages in `requirements.txt`, then run:

```powershell
python src/run_evaluation.py
```

The unified runner writes pooled-WMAPE outputs under `results/tables/`:

- `evaluation_summary.csv` (model-level pooled WMAPE)
- `evaluation_monthly.csv` (monthly pooled WMAPE)
- `evaluation_sku_wmape.csv` (individual SKU pooled WMAPE)

Example variants:

```powershell
python src/run_evaluation.py --demand-types erratic --models xgboost,lightgbm,random_forest,lumpy_hurdle
python src/run_evaluation.py --demand-types erratic --models chronos:amazon/chronos-2
```

## Models

The modelling code from the original notebooks is now organised rather than removed:

- `src/models/benchmarks.py`: naive, seasonal naive, 3- and 6-month moving averages, Croston, SBA, and TSB.
- `src/models/advanced.py`: XGBoost, LightGBM, Random Forest, and the two-stage LightGBM hurdle model for lumpy demand.

Run `python src/run_benchmarks.py` to reproduce baseline rolling-origin validation. It writes `benchmark_metrics.csv` and `benchmark_forecasts.csv` to `results/tables/`. The collision subset contains 28 months, so this runner uses an 18-month initial training window; the original notebook's 36-month window is still available in the function but cannot create a test fold with this data.

Run `python src/run_advanced_models.py` to execute XGBoost, LightGBM, Random Forest, and the LightGBM hurdle model across the 8 processed datasets (4 demand types x 2 variants) using a final-month holdout evaluation window. It writes:

- `results/tables/advanced_metrics_all_datasets.csv`
- `results/tables/advanced_forecasts_all_datasets.csv`
- `results/figures/advanced_model_wmape_all_datasets.png`
- persisted trained artifacts in `results/models/advanced/*.joblib`

## Local SKU search app

This repo now includes a local backend and frontend for SKU-level model lookup.

What it does:

- Search by `sku_id`.
- Detect the SKU demand type in each variant (`all_sku_history`, `collision_flag_only`).
- Pick the assigned model per SKU from `results/tables/best_model_per_sku.csv` (when present), with fallback to demand-type-level assignment from `results/tables/advanced_metrics_all_datasets.csv`.
- Run the assigned model to generate a live 2-month forecast horizon for that SKU.
- Show the model WMAPE and prescribed forecast history for that SKU from `results/tables/advanced_forecasts_all_datasets.csv`.

Skeleton input template for per-SKU assignment is provided at:

- `results/tables/best_model_per_sku.template.csv`

Run locally:

```powershell
pip install -r requirements.txt
uvicorn app.backend.server:app --reload
```

Then open `http://127.0.0.1:8000`.

## Demand-type definitions

The classification uses average demand interval (ADI) and squared coefficient of variation (CV²), calculated from positive monthly demand.

| Demand type | Rule |
| --- | --- |
| Smooth | ADI ≤ 1.32 and CV² ≤ 0.49 |
| Intermittent | ADI > 1.32 and CV² ≤ 0.49 |
| Erratic | ADI ≤ 1.32 and CV² > 0.49 |
| Lumpy | ADI > 1.32 and CV² > 0.49 |

SKUs with no observed demand are kept separately as `collision_sales_no_demand.csv`, rather than being forced into one of the four analytic demand types.
